# 开发启动与部署

## 本地准备

安装 Flutter stable、Android Studio、Android SDK 和 Visual Studio 2022 的 C++ 桌面开发组件。另准备 MySQL 8.x 和轻量 REST API 运行环境：

~~~powershell
flutter doctor -v
flutter config --enable-windows-desktop
flutter devices
~~~

客户端项目建立后复制 .env.example 为本地配置，至少包含 API_BASE_URL 和 APP_ENV=development。服务端配置至少包含 MYSQL_URL、JWT_SECRET、ACCESS_TOKEN_EXPIRES_IN、REFRESH_TOKEN_EXPIRES_IN、ATTACHMENT_DIR、SMTP_HOST、SMTP_PORT、SMTP_USER 和 SMTP_PASSWORD。邮件发送层使用 Nodemailer，具体 SMTP 服务商可后续替换。

## 开发检查

~~~powershell
flutter pub get
dart format --set-exit-if-changed .
flutter analyze
flutter test
flutter run -d windows
flutter run -d android
~~~

每次数据库变更新增 migration；先本地 MySQL 执行，再在 staging 验证，最后人工审批进入个人生产环境。

## 环境

- development：本地 MySQL 与本地 API，允许测试数据。
- staging：独立 MySQL/API，用于真机、同步和发布前验收。
- production：已有 Linux 轻量云服务器上的 MySQL/API、最小权限账号、备份和日志；通过已有域名和 HTTPS 提供访问。

客户端通过 --dart-define 注入环境配置，生产构建禁止读取开发配置。云端附件目录必须位于应用运行目录之外或明确的数据目录，并纳入独立备份；不得提交 Git。

## 发布

Android 生成签名密钥并放入密码管理器；构建 release APK，复制到个人设备安装。Windows 构建 release 并生成可运行目录或安装包。无需应用商店发布，但仍应保管签名文件和版本号。

## 回滚与应急

客户端迁移必须向前兼容，不能依赖破坏性降级。服务端迁移使用 expand/contract：先加字段和兼容逻辑，再切换读写，最后清理旧字段。

发生同步事故时：暂停写接口 → 保留 sync_operations 和 sync_changes → 从备份恢复到临时库验证 → 修复后恢复服务。附件目录和 MySQL 必须分别备份。

## 首次开发顺序

先完成阶段 0，再实现本地任务闭环，最后接入 Auth 与同步。同步协议稳定前不开发复杂 UI；应尽早用两个客户端做断网、并发、重复请求和进程终止测试。
