# 开发启动与部署

当前版本：`1.1.4`；Android build number 为 `6`。

## 环境准备

- Windows 11。
- Flutter stable 与 Dart。
- Android Studio、Android SDK；真机调试需要 USB 调试或 Android 模拟器。
- Visual Studio Community，安装“使用 C++ 的桌面开发”组件，用于 Windows 构建。
- Inno Setup 7，用于生成 Windows 安装包。

确认环境：

~~~powershell
flutter doctor -v
flutter devices
~~~

## 本地启动与检查

在项目根目录执行：

~~~powershell
flutter pub get
dart run build_runner build --delete-conflicting-outputs
dart format .
flutter analyze
flutter test
flutter run -d windows
~~~

Android 真机或模拟器就绪后：

~~~powershell
flutter run -d android
~~~

首次启动 Android 端会申请通知与精确闹钟权限，不再申请全屏提醒权限。拒绝精确闹钟权限时，应用仍会尝试使用系统允许的非精确提醒。旧版安装后首次运行会把原有截止时间视为含具体时分，避免迁移时改变旧任务的提醒时刻。

当前版本不需要 MySQL、Node.js、SMTP 或任何 `.env` 配置；这些仅在后续云端开发时使用。

## Windows 构建与安装包

~~~powershell
.\installer\build-installer.ps1
~~~

脚本会获取依赖、生成 Drift 代码、构建 Windows Release，并调用 Inno Setup 7。1.1.4 安装包为 `installer/output/TodoList-Setup-1.1.4.exe`。它面向 x64 Windows，安装过程中会检测并在缺失时下载 Microsoft Visual C++ x64 运行库。

Windows 提醒使用独立 Flutter 窗口绘制圆角提醒卡片并播放系统提示音，不依赖 Windows Toast 注册。提醒期间应用必须保持运行，可把主窗口隐藏到托盘，但从托盘彻底退出后不会触发提醒。

提醒冒烟测试：从托盘彻底退出旧版，安装当前构建的安装包，创建一条未来 2～3 分钟提醒的未完成任务，再关闭主窗口使应用驻留托盘；到点检查右下角弹窗及提示音。若未显示，先确认新进程已启动、任务仍未完成、提醒时间在将来。

## Android APK 构建

~~~powershell
flutter build apk --release
~~~

输出文件为 `build/app/outputs/flutter-apk/app-release.apk`，1.1.4 包内版本号为 `1.1.4`、build number 为 `6`。当前 `android/app/build.gradle.kts` 仍使用调试密钥签署 Release APK，可用于本地安装测试；公开分发或上架前须配置并妥善保管专用发布密钥。首次构建时 Gradle 会下载自身和 Android 构建依赖；如果出现 Gradle 文件独占锁超时，先关闭其他 Android Studio、Gradle 或 Java 构建进程后重试。网络连接中断时重试构建即可。通知提醒依赖 Android 系统权限，部分厂商的后台限制可能造成提醒延迟。

Android 冒烟测试：安装 APK 后，允许通知与精确闹钟权限；请新建一条未来 2～3 分钟提醒的未完成任务，分别在亮屏与锁屏状态等待。确认不弹出全屏闹钟页，通知栏有任务提醒、铃声响起；点击提醒应停止铃声并打开应用，滚动定位到对应任务。若未响铃，检查闹钟音量、TodoList 的“待办闹钟提醒”通知频道，以及小米系统的后台运行/省电限制。
