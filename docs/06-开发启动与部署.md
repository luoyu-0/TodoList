# 开发启动与部署

## 环境准备

- Windows 11。
- Flutter stable 与 Dart。
- Android Studio、Android SDK；真机调试需要 USB 调试或 Android 模拟器。
- Visual Studio Community，安装“使用 C++ 的桌面开发”组件，用于 Windows 构建。
- Inno Setup 7，用于生成 Windows 安装包。

确认环境：

~~~powershell
flutter doctor -v
flutter devices
~~~

## 本地启动与检查

在项目根目录执行：

~~~powershell
flutter pub get
dart run build_runner build --delete-conflicting-outputs
dart format .
flutter analyze
flutter test
flutter run -d windows
~~~

Android 真机或模拟器就绪后：

~~~powershell
flutter run -d android
~~~

当前版本不需要 MySQL、Node.js、SMTP 或任何 `.env` 配置；这些仅在后续云端开发时使用。

## Windows 构建与安装包

~~~powershell
.\installer\build-installer.ps1
~~~

脚本会获取依赖、生成 Drift 代码、构建 Windows Release，并调用 Inno Setup 7。安装包输出到 `installer/output/`。它面向 x64 Windows，安装过程中会检测并在缺失时下载 Microsoft Visual C++ x64 运行库。

## Android APK 构建

~~~powershell
flutter build apk --release
~~~

输出文件为 `build/app/outputs/flutter-apk/app-release.apk`。首次构建时 Gradle 会下载自身和 Android 构建依赖；如果出现 Gradle 文件独占锁超时，先关闭其他 Android Studio、Gradle 或 Java 构建进程后重试。网络连接中断时重试构建即可。

## 后续云端部署

云端恢复开发后再配置 Linux 服务器上的 Node.js、Fastify、Prisma、MySQL、Nodemailer SMTP、HTTPS 反向代理、附件目录和备份任务。部署前应补充环境变量模板、数据库迁移流程、日志与健康检查。
