# 接口与安全设计

## 认证与权限

后端自行实现邮箱 + 密码登录，密码使用 Argon2id 或 bcrypt 哈希，登录后签发短期 access token 与可撤销 refresh token。客户端只保存 Token，不保存明文密码；退出时清理本地会话。

邮箱真实性通过注册验证保证，而不是依赖格式校验：注册后通过 SMTP 邮件服务发送 6 位一次性验证码，验证码有效期 10 分钟、最多尝试 5 次、发送间隔至少 60 秒；code 只保存哈希。只有 email_verified_at 非空的用户才能登录并使用云同步。另提供“重新发送”和“忘记密码”流程，并对邮箱和 IP 做频率限制。

API 层统一按 token 中的 user_id 做数据隔离。所有 SQL 必须带 user_id 过滤；使用参数化查询和最小数据库账号权限。首发不做账号间共享，仅允许同一账号多设备同步。

所有 API 都要校验 token、请求体 schema、资源归属和操作权限，不能信任客户端传来的 user_id。

## 数据安全

- 全链路 HTTPS/TLS；MySQL 开启自动备份和定期恢复演练。
- 数据库密码、JWT 密钥和附件存储路径通过服务端环境变量管理，不提交仓库。
- 限制输入长度、枚举、批量大小和请求频率。
- 附件只允许配置的 MIME 类型，服务端再次检查真实文件类型和大小；单文件最大 10 MB，文件名不直接用于磁盘路径，下载必须经过鉴权。
- refresh token 使用随机高熵值，仅存哈希，支持过期和撤销。
- 邮件 SMTP 凭据只存在服务端环境变量；验证码邮件内容不包含密码和任务数据。
- 账号删除采用异步任务：撤销会话 → 删除成员/数据 → 删除 Auth 用户。
- 提供 JSON/CSV 导出，导出链接短时有效且不写入日志。

## 错误与可观测性

统一返回 code、message、request_id。客户端分别处理 unauthorized、forbidden、validation_error、conflict、rate_limited 和 temporary_unavailable。

记录请求耗时、同步批次、失败类型、版本和匿名用户标识；不记录任务标题、备注和 Token。首版至少提供 API 访问日志、客户端错误上报和健康检查。
