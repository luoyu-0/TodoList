# 数据模型与后续同步协议

## 当前 SQLite 数据模型

### task_lists

- `id`：主键。
- `name`：清单名称；当前默认清单为“收件箱”。
- `sort_mode`：`createdAt`、`title`、`dueAt` 或 `manual`。
- `expand_subtasks`：任务列表是否默认展开子任务；`show_subtasks_in_pin`：Windows pin 模式是否显示子任务。
- `archived`、`created_at`、`updated_at`。

### tasks

- `id`、`list_id`、`parent_task_id`：子任务引用父任务；新建时最多允许三层，子任务仍保有完整任务字段。历史数据中的更深层任务仍保留。
- `title`：任务标题。
- `note`：可选备注。
- `completed`、`priority`、`sort_order`。
- `due_at`：可选截止日期及具体时间；全天任务以所选日期零点保存。
- `due_has_time`：是否设置了具体截止时分；旧数据迁移时置为 `true`，保留原来的时间含义。
- `reminder_at`：首次提醒的可选独立时间；新任务设置截止日期时填入默认时间，之后独立保存。旧任务此值为空时按截止时间计算；全天任务默认在截止日 09:00 提醒。
- `reminder_enabled`：是否调度该任务的首次与额外提醒；默认开启。关闭时保留所有提醒时间，重新开启后可继续使用。
- `task_reminders`：额外提醒时间表，按任务 ID 关联；一条任务可以有多条额外提醒。
- `created_at`、`updated_at`、`deleted_at`。

### task_attachments

已预留附件元数据表：`id`、`task_id`、`file_name`、`mime_type`、`size_bytes`、`local_path`、`remote_path`、`created_at`、`deleted_at`。当前尚未提供附件选择、复制、查看或上传界面。

## 删除与保留

普通删除写入 `deleted_at`，使任务从收件箱隐藏并在应用内回收站可见。主任务删除、恢复或永久删除会递归作用于后代；单独恢复子任务时会恢复祖先。永久删除会删除相关任务、提醒及附件元数据。`purgeExpiredTrash` 会清理删除时间超过 30 天的任务。

## 后续同步协议

云端实现后，客户端维护 `last_change_id` 和待同步操作队列：

1. `pull(after_change_id)` 拉取服务端变更，事务更新 SQLite 后推进游标。
2. `push(operations[])` 提交本地操作，服务端以 `operation_id` 做幂等约束。

建议接口为 `POST /api/v1/sync/push` 与 `GET /api/v1/sync/pull?after=...`。不同字段并发修改可按字段时间戳合并；同一字段冲突采用最后写入胜出。上述同步机制尚未实现。
