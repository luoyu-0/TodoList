# 数据模型与后续同步协议

## 当前 SQLite 数据模型

### task_lists

- `id`：主键。
- `name`：清单名称；当前默认清单为“收件箱”。
- `sort_mode`：`createdAt`、`title`、`dueAt` 或 `manual`。
- `archived`、`created_at`、`updated_at`。

### tasks

- `id`、`list_id`、`parent_task_id`。
- `title`：任务标题。
- `note`：可选备注。
- `completed`、`priority`、`sort_order`。
- `due_at`：可选截止日期。
- `created_at`、`updated_at`、`deleted_at`。

### task_attachments

已预留附件元数据表：`id`、`task_id`、`file_name`、`mime_type`、`size_bytes`、`local_path`、`remote_path`、`created_at`、`deleted_at`。当前尚未提供附件选择、复制、查看或上传界面。

## 删除与保留

普通删除写入 `deleted_at`，使任务从收件箱隐藏并在应用内回收站可见。恢复会清空 `deleted_at`；永久删除会删除任务及其附件元数据。`purgeExpiredTrash` 会清理删除时间超过 30 天的任务。

## 后续同步协议

云端实现后，客户端维护 `last_change_id` 和待同步操作队列：

1. `pull(after_change_id)` 拉取服务端变更，事务更新 SQLite 后推进游标。
2. `push(operations[])` 提交本地操作，服务端以 `operation_id` 做幂等约束。

建议接口为 `POST /api/v1/sync/push` 与 `GET /api/v1/sync/pull?after=...`。不同字段并发修改可按字段时间戳合并；同一字段冲突采用最后写入胜出。上述同步机制尚未实现。
