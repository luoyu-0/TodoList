# 技术架构与工程规范

## 当前实现

| 层 | 技术 | 说明 |
|---|---|---|
| 客户端 | Flutter + Dart | 共用 Windows 与 Android 的业务和界面代码 |
| 页面状态 | StatefulWidget | 当前本地 MVP 使用轻量状态管理，尚未接入 Riverpod |
| 本地数据 | Drift + SQLite | 保存默认收件箱、任务和附件元数据 |
| Windows 集成 | window_manager、tray_manager | 自绘窗口栏、桌面固定、窗口状态和系统托盘 |
| 图标 | fluentui_system_icons | Windows 端固定与取消固定图标 |
| 安装包 | Inno Setup 7 | 生成 Windows x64 安装程序 |
| 测试 | flutter_test | 目前包含首页基础组件测试 |

主要代码位于：

~~~text
lib/
  main.dart                    # 界面、窗口和托盘交互
  data/local/app_database.dart # Drift 表、迁移和本地数据操作
test/
  widget_test.dart              # 基础组件测试
installer/                      # Windows 安装脚本与说明
~~~

## 本地数据原则

- SQLite 是当前唯一真实数据源，不依赖网络。
- 数据库迁移版本当前为 3：版本 2 添加任务手动排序字段，版本 3 添加清单排序模式字段。
- 所有任务删除均为软删除，永久删除才移除记录及其附件元数据。
- 拖动排序不在每次拖动后立即写入数据库，避免 Drift 流触发整列任务重建造成视觉闪动。

## 后续云端架构

云端功能恢复后采用 Node.js + Fastify + Prisma + MySQL。客户端应增加 Repository、认证模块、远程 API 客户端和同步引擎；SQLite 仍是界面读取来源，云端只作为同步副本。当前仓库中的 `server/` 仅为方案骨架，不能视为可用同步服务。

## 工程规范

- 代码、注释、README 和 docs 使用简体中文；代码标识符和技术专有名词保留英文。
- 修改数据库表后执行 `dart run build_runner build --delete-conflicting-outputs` 更新 Drift 生成代码。
- 提交前执行 `dart format .`、`flutter analyze` 和 `flutter test`。
- 不提交本地数据库、构建产物、密码、Token 或 SMTP 凭据。
