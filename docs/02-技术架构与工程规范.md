# 技术架构与工程规范

## 技术栈

| 层 | 选择 | 作用 |
|---|---|---|
| 客户端 | Flutter + Dart | Windows 11 与 Android 共用 UI 和业务代码 |
| 状态管理 | Riverpod | 可测试的状态编排 |
| 路由 | go_router | 登录守卫和深链接 |
| 本地库 | Drift + SQLite | 离线读写、事务、迁移和同步队列 |
| 云端数据库 | MySQL 8.x | 用户、清单、任务、同步记录和验证记录 |
| 后端 API | 轻量 REST API（Node.js + Fastify + Prisma） | 邮箱认证、同步、附件元数据和数据管理 |
| 实时机制 | 客户端定时拉取 + 手动同步 | 100 人以内优先保证简单可靠，不引入复杂实时基础设施 |
| 测试 | flutter_test、integration_test、MySQL 测试库 | 单元、组件、端到端和故障测试 |
| CI/CD | GitHub Actions | 检查、构建签名包和发布制品 |

## 分层

UI 只负责展示和用户意图；Controller/Notifier 负责编排；Repository 负责本地库与云端；同步引擎负责队列、游标、冲突和重试；REST API 负责认证、权限和持久化。主列表不能直接绕过 Repository 查询云端。

## 建议目录

~~~text
lib/
  app/                 # 入口、主题、路由、环境
  core/                # 错误、日志、网络、时间
  auth/
  features/            # inbox、lists、tasks、sharing、settings
  data/local/          # Drift 表、DAO、迁移
  data/remote/         # REST client、DTO
  data/repositories/
  data/sync/           # 队列、拉取、推送、冲突
test/
integration_test/
server/
  src/
  prisma/
  storage/             # 云端附件目录，不提交 Git
~~~

## 规范

- 数据库存 UTC，展示层按设备时区转换；ID 使用 UUID。
- 所有远程写入带 operation_id，服务端做幂等约束。
- 客户端游客数据不得发送到服务端；只有登录态 Repository 才能调用云端 API。
- 提交前执行 dart format、flutter analyze、flutter test。
- 日志不输出密码、Token、任务内容和邀请链接。
- 数据库迁移只增不改，破坏性变更先做兼容迁移。
- 代码、提交信息、README 与 docs 默认使用简体中文，代码标识符使用英文。
